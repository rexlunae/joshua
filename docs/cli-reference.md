# CLI reference

Generated by `scripts/gen-cli-reference.sh` from `joshua --help` (built
with `--features distributed`; commands marked *experimental* need that
feature).  Every flag that has an `[env: ...]` line can also be set through
that environment variable; an explicit flag wins over the variable.

`serve`, `run`, `bench` and `ppl` share one set of model-load flags
(`--n-ctx`, `--device`, the page-cache, expert-cache, placement,
speculative-decoding and NPU flags), so a benchmark or perplexity run loads
the model exactly as the server would.

```text
An mmap-based LLM inference engine for the Rust ecosystem — a Rust clone of Cactus

Usage: joshua <COMMAND>

Commands:
  cluster-run  Run CPU DeepSeek V4 generation on an explicit static cluster (experimental)
  worker       Serve pipeline stages assigned by a controller, starting without a model (experimental, CPU Qwen3 dense). Each controller streams this worker only its stage's tensors; set JOSHUA_CLUSTER_KEY on both
  serve        Start the OpenAI-compatible HTTP API server
  route        Route whole requests across independent `joshua serve` workers
  run          Run a single chat completion and print the response
  bench        Run a repeatable generation benchmark and print throughput
  ppl          Score text and report perplexity — a data-driven quality measurement for a checkpoint (compare a compressed model against its source on the same corpus)
  report       Print host, model, and build information for a benchmark report
  transcribe   Transcribe a WAV file with a Whisper model
  embed        Embed one or more texts and print their vector representations
  help         Print this message or the help of the given subcommand(s)

Options:
  -h, --help     Print help
  -V, --version  Print version
```

## `joshua serve`

```text
Start the OpenAI-compatible HTTP API server

Usage: joshua serve [OPTIONS]

Options:
  -m, --model <MODEL>
          Path to the GGUF model file, or to a directory of models.  A directory is served as --model-dir serves it — every model in it is listed and selectable by name — and the server starts on the model it finds there.  Optional with --model-dir, where every model is loaded by the first request that names it
          
          [env: JOSHUA_MODEL_PATH=]

      --model-dir <MODEL_DIR>
          Enable POST /v1/models/load and /v1/models/unload for models in this directory, which GET /v1/models also lists.  A request selects one by its listed id, and the first request that names it loads it. Protect the API with --api-key when it is not bound to localhost
          
          [env: JOSHUA_MODEL_DIR=]

      --worker <WORKERS>
          Model-less workers (`joshua worker`) this controller may place models on; loads go to all of them unless a request names some or asks for a local load.  Needs JOSHUA_CLUSTER_KEY

  -a, --addr <ADDR>
          Address to listen on.  Defaults to localhost; bind `0.0.0.0` only after enabling `--api-key` and/or TLS, since the API is otherwise unauthenticated
          
          [default: 127.0.0.1:8080]

      --n-ctx <N_CTX>
          Context window size in tokens (prompt + generated), fixed at load: it sizes the KV cache and RoPE tables.  On `serve`, a request may ask for a smaller window with `context_window` (or `num_ctx`), never a larger one
          
          [env: JOSHUA_N_CTX=]
          [default: 4096]

      --device <DEVICE>
          Compute backend: auto, cpu, metal, cuda, opencl, vulkan, or sycl. An explicit GPU request fails the load when the backend is not built in or is unavailable at runtime

          Possible values:
          - auto:   Best backend this build supports, tried in order: CUDA, Metal, OpenCL, Vulkan, SYCL, then CPU
          - cpu:    CPU inference
          - metal:  Apple Metal (build with `--features metal`)
          - cuda:   NVIDIA CUDA (build with `--features cuda`)
          - opencl: OpenCL (Intel iGPU/Arc or any OpenCL ICD; build with `--features opencl`; use `--device opencl`)
          - vulkan: Vulkan (AMD RADV / Intel ANV / any Vulkan ICD; build with `--features vulkan`; use `--device vulkan`). Bring-up target is the AMD Renoir iGPU
          - sycl:   SYCL 2020 (Intel oneAPI/LLVM `--features sycl` bridge via a dynamically loaded libjoshua_sycl; build with `--features sycl`; use `--device sycl`)
          
          [env: JOSHUA_DEVICE=]
          [default: auto]

      --huge-pages <HUGE_PAGES>
          Physical-memory backing for the model: off, transparent, huge, 2mb, or 1gb (Linux only for the huge-page modes).  Defaults to transparent on Linux (best-effort 2 MiB pages), off elsewhere

          Possible values:
          - off:         Normal pages; file-backed mmap shared via the page cache (the default off Linux — `transparent` is the Linux default)
          - transparent: Transparent huge pages (MADV_HUGEPAGE) on the file-backed mmap; the default on Linux, where it is best-effort and silently keeps normal pages when the kernel cannot honour them
          - huge:        Explicit huge pages at the system default size (anonymous copy)
          - 2mb:         Explicit 2 MiB "large" pages (anonymous copy)
          - 1gb:         Explicit 1 GiB "huge" pages (anonymous copy)
          
          [default: transparent]

      --mmap
          Require the model to be memory-mappable: a compressed model file (a gzip/zstd/... stream, or one the filesystem stores compressed) becomes a load error instead of a warning

      --lazy-weights
          Optimise the mapping for a model far larger than RAM: no readahead, so pages fault in only as weights are genuinely touched
          
          [env: JOSHUA_LAZY_WEIGHTS=]

      --prefetch-model [<PREFETCH_MODEL>]
          Prefetch the whole model file into the OS page cache at load (MADV_WILLNEED), so a model that fits in RAM is fully resident before the first request and inference never re-reads weights from disk.  Defaults to on when the model file fits in RAM; pass `--prefetch-model=false` to force it off
          
          [env: JOSHUA_PREFETCH_MODEL=]
          [possible values: true, false]

      --pin-hot-weights [<PIN_HOT_WEIGHTS>]
          Prefetch the always-touched weights (embeddings, norms, attention, routers, shared experts, output) at load and advise random access on routed experts, so the per-token working set stays resident. Defaults to on when the model file is larger than RAM; pass `--pin-hot-weights=false` to force it off
          
          [env: JOSHUA_PIN_HOT_WEIGHTS=]
          [possible values: true, false]

      --pin-hot-experts <PIN_HOT_EXPERTS>
          Keep the N most frequently routed experts resident (routing- frequency LRU; recency as the tie-break).  0 disables.  Wired for the joshua-native MoE loaders (deepseek2, deepseek4, qwen3moe)
          
          [env: JOSHUA_PIN_HOT_EXPERTS=]
          [default: 0]

      --expert-cache <EXPERT_CACHE>
          Size the hot-expert cache automatically at load (`auto`), or set a fixed expert count.  Overrides --pin-hot-experts when given a count
          
          [env: JOSHUA_EXPERT_CACHE=]

      --vram-expert-cache <VRAM_EXPERT_CACHE>
          Size the bounded VRAM expert cache (#62): upload a hot subset of the routed experts to the accelerator.  `auto` derives the device byte budget at load (device free − dense − headroom − KV); a number is a fixed MiB budget; `0` disables (all experts stay on the host). Unset (the default), `--expert-placement auto` engages the cache itself where the leftover device memory is worth it (#110)
          
          [env: JOSHUA_VRAM_EXPERT_CACHE=]

      --ssd-expert-cache <SSD_EXPERT_CACHE>
          Size the Tier-3 NVMe/SSD expert staging slab (`--ssd-expert-cache`): a bounded host-RAM slab that `pread(2)`-streams a hot subset of the routed experts off the SSD (see `NvmeResidency`).  `auto` derives the host-RAM byte budget from the machine's available RAM at load; a number is a fixed MiB budget; `0` disables (experts keep their ordinary host page-cache residency)
          
          [env: JOSHUA_SSD_EXPERT_CACHE=]

      --prefill-chunk <PREFILL_CHUNK>
          Tokens per prefill chunk (default 512).  Bounds the per-layer prefill workspace and sets how many prompt rows each routed expert sees per matmul; the joshua-native MoE loaders read each layer's weights once per prefill whatever the chunk
          
          [env: JOSHUA_PREFILL_CHUNK=]

      --prefill-budget-ms <PREFILL_BUDGET_MS>
          Target wall time for one prefill chunk, in milliseconds.  When non-zero, architectures that prefill chunk by chunk choose each chunk from an online cost model; `--prefill-chunk` is the ceiling. 0 (the default) keeps the fixed chunk size
          
          [env: JOSHUA_PREFILL_BUDGET_MS=]

      --speculative <SPECULATIVE>
          Speculative token generation: draft up to N tokens per step by prompt lookup (the continuation of the latest earlier occurrence of the output's trailing n-gram) and verify them in one forward pass.  Output is unchanged; repetitive output (code edits, quoted context, tool-call arguments) decodes in fewer weight sweeps. `0` (the default) disables it.  Applies to the loaders that can score every position and roll their KV cache back: the plain- attention qwen family (qwen, qwen2moe, qwen2vl, qwen3, qwen3moe, qwen3vl, qwen3vlmoe, chatglm, glm4, glm4moe), the deepseek2 family (deepseek, deepseek2, glm-dsa — incl. V3 / Kimi-K2 / GLM-5), and deepseek4 / deepseek41.  Models with recurrent DeltaNet or KDA layers (qwen3next, qwen3.5, qwen4exp, glm5next, kimi-linear, kimi-k3) and candle's stock loaders cannot roll their KV cache back; there the flag is ignored with a warning
          
          [env: JOSHUA_SPECULATIVE=]

      --mtp <MTP>
          MTP drafting: draft up to N tokens per step (at most 7) with the model's own NextN / MTP block, which GLM-4.5+ and Qwen3.5/3.6 GGUFs carry, and verify them in one forward pass.  Output is unchanged.  Replaces --speculative's prompt lookup on a model with the block and is ignored with a warning on one without.  Every forward pass also runs through the block (one more layer).  `0` (the default) disables it and skips loading the block
          
          [env: JOSHUA_MTP=]

      --draft-model <DRAFT_MODEL>
          Draft-model speculative decoding: a small GGUF that shares this model's tokenizer (e.g. Qwen3-0.6B for a Qwen3 MoE) drafts up to --draft-max tokens per step, verified in one forward pass of this model.  Greedy output is unchanged; sampled output is verified against the draft's own distribution, so it is distributed as plain sampling.  The draft must be an attention-only model of a joshua-native loader (qwen3, qwen3moe, glm4, deepseek2, …) and runs on the dense device.  Takes the place of --speculative's prompt lookup and of --mtp
          
          [env: JOSHUA_DRAFT_MODEL=]

      --draft-max <DRAFT_MAX>
          Most draft-model tokens per step (default 4)
          
          [env: JOSHUA_DRAFT_MAX=]

      --mlock-hot-weights [<MLOCK_HOT_WEIGHTS>]
          Lock the always-touched weights into RAM (mlock).  Needs the process memlock limit to cover the hot set: `LimitMEMLOCK=infinity` (systemd), `ulimit -l unlimited`, or /etc/security/limits.conf. On a systemd *user* session the hard limit is inherited from the login session, so a unit's LimitMEMLOCK alone is silently capped — apply `sudo prlimit --pid <user manager pid> --memlock=-1:-1` for a live fix, or re-login.  `=required` fails the load instead of degrading when the limit is too low; the limit is checked before any mlock attempt, with one warning naming limit vs required size

          Possible values:
          - on:       Lock the hot set; degrade to advisory pinning (with a warning) when the memlock limit is too low
          - required: Lock the hot set; fail the load when the memlock limit is too low
          - off:      Do not lock (explicitly disable, overriding an env var)
          
          [env: JOSHUA_MLOCK_HOT_WEIGHTS=]

      --mlock-weight-budget <MiB>
          Cap locked weight pages in MiB when the full dense set exceeds RAM. Requires --mlock-hot-weights; skips untied input embeddings and routed experts. Leave RAM for KV state and disk staging

      --expert-placement <EXPERT_PLACEMENT>
          Where a MoE model's routed experts live on a GPU: `device` uploads them (the whole model must fit), `host` keeps them in RAM borrowed from the mapping with only the dense set on the GPU (runs models larger than VRAM), `auto` picks `device` only when the model fits the GPU's free memory with headroom.  Ignored on the CPU.  When `auto` falls back to `host` on an architecture that can run routed experts from a bounded VRAM cache (deepseek4 on OpenCL/SYCL), that cache is engaged by default where the leftover device memory is worth it (#110); `--vram-expert-cache 0` opts out
          
          [env: JOSHUA_EXPERT_PLACEMENT=]
          [default: auto]

      --vram-budget <VRAM_BUDGET>
          GPU memory the model may use, in MiB.  Overrides the probe for the `--expert-placement auto` decision and the per-GPU session cap; the way to state the budget on backends without a probe (Metal, OpenCL) or when sharing the card
          
          [env: JOSHUA_VRAM_BUDGET=]

      --npu-plugin <NPU_PLUGIN>
          NPU vendor plugin (a cdylib exporting the joshua_npu_* ABI)
          
          [env: JOSHUA_NPU_PLUGIN=]

      --npu-in-process
          Load the NPU plugin in-process instead of the isolated shim (lower overhead; a plugin crash takes the server down)

      --engram-tier <ENGRAM_TIER>
          Where a DeepSeek-V4.1 model's Engram n-gram tables are resident (a separate policy from the routed experts): `auto` resolves them straight from the mmap mapping (disk-pinned) and promotes a working subset into RAM only when free RAM is ample (>~192 GiB), `ram` always promotes the working subset into RAM, `disk` always pins them to storage.  The tables never consume a Tier-1 VRAM or Tier-2 host-slot budget under any tier
          
          [env: JOSHUA_ENGRAM_TIER=]
          [default: auto]

      --dense-placement <DENSE_PLACEMENT>
          Where the dense set (embeddings, norms, attention, routers, shared experts, output) runs on a GPU: `device` offloads it (right for a real GPU whose GEMM beats CPU-BLAS), `cpu` keeps it on CPU-BLAS (right when the accelerator is a weak iGPU / software OpenCL-Vulkan path that is slower than the CPU), `auto` runs a quick startup probe and picks by measured throughput.  Ignored on the CPU
          
          [env: JOSHUA_DENSE_PLACEMENT=]
          [default: auto]

      --skip-placement-bench [<SKIP_PLACEMENT_BENCH>]
          Skip the `--dense auto` startup probe (fast launch).  `auto` then keeps its historical on-device default, still gated on the dense set fitting the device memory budget (#176)
          
          [env: JOSHUA_SKIP_PLACEMENT_BENCH=]
          [default: false]
          [possible values: true, false]

      --prefix-checkpoints <PREFIX_CHECKPOINTS>
          Prefix checkpoints kept per session of a model with recurrent layers (Qwen3-Next, Qwen3.5, Qwen3.8-Flash-Next, Kimi-Linear): copies of the running state at each prompt boundary, so an edited conversation resumes from the latest one instead of re-reading the whole prompt.  Each costs one copy of that state per pooled session; 0 turns them off (default 4)
          
          [env: JOSHUA_PREFIX_CHECKPOINTS=]

      --prefix-cache-mib <PREFIX_CACHE_MIB>
          Host RAM (MiB) for the prefix cache: the state at the end of each client's system prompt, so a new chat skips re-reading it, and the state of conversations the warm session pool lets go of, so they resume without re-reading their history.  Qwen-family and deepseek2 models.  Default: an eighth of the free RAM at start, at most 4096; 0 turns it off
          
          [env: JOSHUA_PREFIX_CACHE_MIB=]

      --prefix-cache-root-min <PREFIX_CACHE_ROOT_MIN>
          Shortest system prompt (tokens) kept in the prefix cache; a shorter one is cheaper to read again (default 1024)
          
          [env: JOSHUA_PREFIX_CACHE_ROOT_MIN=]

      --env-to-user
          Move an `<env>` block (working directory, today's date, as opencode writes it) out of the system prompt into the first user message, so a new folder or a new day does not change the system prompt and the prefix cache still covers it.  The model sees the same lines, one message later
          
          [env: JOSHUA_ENV_TO_USER=]

      --whisper-model <WHISPER_MODEL>
          Whisper model directory to mount at /v1/audio/transcriptions
          
          [env: JOSHUA_WHISPER_MODEL=]

      --max-concurrency <MAX_CONCURRENCY>
          Maximum concurrent generations/embeddings; excess requests get a 503.  Bounds peak memory from concurrent model instances. Defaults to the machine's parallelism
          
          [env: JOSHUA_MAX_CONCURRENCY=]

      --queue-timeout-ms <QUEUE_TIMEOUT_MS>
          How long a request may wait for a free concurrency slot before a 503, in milliseconds.  0 (the default) rejects immediately
          
          [env: JOSHUA_QUEUE_TIMEOUT_MS=]

      --admission-queue-depth <ADMISSION_QUEUE_DEPTH>
          How many requests may wait for a concurrency slot when --queue-timeout-ms is non-zero (0 selects the built-in default)
          
          [env: JOSHUA_ADMISSION_QUEUE_DEPTH=]

      --max-output-tokens <MAX_OUTPUT_TOKENS>
          Hard ceiling on tokens generated per request, capping the client-supplied max_tokens.  A request without max_tokens (or with -1) generates until end of sequence or of the context, up to this ceiling (default 4096)
          
          [env: JOSHUA_MAX_OUTPUT_TOKENS=]

      --temp <TEMP>
          Default temperature for requests that set none
          
          [env: JOSHUA_TEMP=]

      --top-k <TOP_K>
          Default top-k (0 = off)
          
          [env: JOSHUA_TOP_K=]

      --top-p <TOP_P>
          Default top-p (1.0 = off)
          
          [env: JOSHUA_TOP_P=]

      --min-p <MIN_P>
          Default min-p (0 = off)
          
          [env: JOSHUA_MIN_P=]

      --typical <TYPICAL>
          Default locally typical sampling p (1.0 = off)
          
          [env: JOSHUA_TYPICAL_P=]

      --repeat-penalty <REPEAT_PENALTY>
          Default repetition penalty (1.0 = off)
          
          [env: JOSHUA_REPEAT_PENALTY=]

      --repeat-last-n <REPEAT_LAST_N>
          Default penalty window in tokens (0 = off, -1 = the context)
          
          [env: JOSHUA_REPEAT_LAST_N=]

      --presence-penalty <PRESENCE_PENALTY>
          Default presence penalty
          
          [env: JOSHUA_PRESENCE_PENALTY=]

      --frequency-penalty <FREQUENCY_PENALTY>
          Default frequency penalty
          
          [env: JOSHUA_FREQUENCY_PENALTY=]

      --xtc-probability <XTC_PROBABILITY>

          [env: JOSHUA_XTC_PROBABILITY=]

      --xtc-threshold <XTC_THRESHOLD>
          Default XTC threshold
          
          [env: JOSHUA_XTC_THRESHOLD=]

      --mirostat <MIROSTAT>
          Default Mirostat version (0 = off, 1, 2)
          
          [env: JOSHUA_MIROSTAT=]

      --mirostat-lr <MIROSTAT_LR>
          Default Mirostat learning rate (eta)
          
          [env: JOSHUA_MIROSTAT_LR=]

      --mirostat-ent <MIROSTAT_ENT>
```

## `joshua route`

```text
Route whole requests across independent `joshua serve` workers.

Each chat/completion/embedding request runs entirely on one worker, chosen by model and load; see docs/request-routing.md.

Usage: joshua route [OPTIONS] --worker <WORKERS>

Options:
      --worker <WORKERS>
          HTTP addresses of `joshua serve` workers, comma-separated or repeated (e.g. `10.0.0.2:8080,10.0.0.3:8080`)
          
          [env: JOSHUA_ROUTE_WORKERS=]

  -a, --addr <ADDR>
          Address to listen on
          
          [default: 127.0.0.1:8090]

      --api-key <API_KEY>
          Require this API key from clients on /v1 routes
          
          [env: JOSHUA_API_KEY=]

      --worker-api-key <WORKER_API_KEY>
          API key to present to workers (their --api-key)
          
          [env: JOSHUA_WORKER_API_KEY=]

      --worker-slots <WORKER_SLOTS>
          Requests in flight per worker; defaults to each worker's reported --max-concurrency

      --queue-depth <QUEUE_DEPTH>
          Requests allowed to wait for a free slot when every worker is full; beyond this the router answers 429
          
          [default: 64]

      --queue-timeout-ms <QUEUE_TIMEOUT_MS>
          Longest a queued request waits for a slot before a 503, in ms
          
          [default: 30000]

      --health-interval-ms <HEALTH_INTERVAL_MS>
          Interval between worker health probes, in ms
          
          [default: 2000]

      --connect-timeout-ms <CONNECT_TIMEOUT_MS>
          Timeout for connecting to a worker and for a health probe, in ms
          
          [default: 2000]

      --response-timeout-ms <RESPONSE_TIMEOUT_MS>
          Longest a dispatched request waits for the worker's first output (the whole JSON response, or the first stream event) before a 504, in ms; 0 waits indefinitely.  Workers compute a completion before sending it, so this also bounds generation time
          
          [default: 600000]

      --max-response-bytes <MAX_RESPONSE_BYTES>
          Largest non-streaming worker response the router buffers, in bytes; larger ones are answered with a 502
          
          [default: 67108864]

      --tls-cert <TLS_CERT>
          Serve HTTPS with this PEM certificate chain (needs --tls-key and a build with the `tls` cargo feature).  Only the client-facing hop is encrypted; worker connections stay plain HTTP
          
          [env: JOSHUA_TLS_CERT=]

      --tls-key <TLS_KEY>
          PEM private key for --tls-cert
          
          [env: JOSHUA_TLS_KEY=]

  -h, --help
          Print help (see a summary with '-h')
```

## `joshua run`

```text
Run a single chat completion and print the response

Usage: joshua run [OPTIONS] --model <MODEL> <PROMPT>

Arguments:
  <PROMPT>
          The user message to send to the model

Options:
  -m, --model <MODEL>
          Path to the GGUF model file
          
          [env: JOSHUA_MODEL_PATH=]

      --max-tokens <MAX_TOKENS>
          Maximum tokens to generate
          
          [default: 256]

      --temperature <TEMPERATURE>
          Sampling temperature (0 = greedy)
          
          [default: 0.7]

          [env: JOSHUA_NPU_PLUGIN=]

          Load the NPU plugin in-process instead of the isolated shim (lower overhead; a plugin crash takes the server down)

          Where a DeepSeek-V4.1 model's Engram n-gram tables are resident (a separate policy from the routed experts): `auto` resolves them straight from the mmap mapping (disk-pinned) and promotes a working subset into RAM only when free RAM is ample (>~192 GiB), `ram` always promotes the working subset into RAM, `disk` always pins them to storage.           [default: auto]

      --dense-placement <DENSE_PLACEMENT>

      --skip-placement-bench [<SKIP_PLACEMENT_BENCH>]
          Skip the `--dense auto` startup probe (fast launch).  `auto` then keeps its historical on-device default, still gated on the dense set fitting the device memory budget (#176)
          
          [env: JOSHUA_SKIP_PLACEMENT_BENCH=]
          [default: false]
          [possible values: true, false]

  -h, --help
          Print help (see a summary with '-h')
```

```text
          - off:         Normal pages; file-backed mmap shared via the page cache (the default off Linux — `transparent` is the Linux default)
          - transparent: Transparent huge pages (MADV_HUGEPAGE) on the file-backed mmap; the default on Linux, where it is best-effort and silently keeps normal pages when the kernel cannot honour them
          - huge:        Explicit huge pages at the system default size (anonymous copy)
          - 2mb:         Explicit 2 MiB "large" pages (anonymous copy)
          - 1gb:         Explicit 1 GiB "huge" pages (anonymous copy)
          
          [default: transparent]

      --mmap
          Require the model to be memory-mappable: a compressed model file (a gzip/zstd/... stream, or one the filesystem stores compressed) becomes a load error instead of a warning

      --lazy-weights
          Optimise the mapping for a model far larger than RAM: no readahead, so pages fault in only as weights are genuinely touched
          
          [env: JOSHUA_LAZY_WEIGHTS=]

      --prefetch-model [<PREFETCH_MODEL>]
          Prefetch the whole model file into the OS page cache at load (MADV_WILLNEED), so a model that fits in RAM is fully resident before the first request and inference never re-reads weights from disk.  Defaults to on when the model file fits in RAM; pass `--prefetch-model=false` to force it off
          
          [env: JOSHUA_PREFETCH_MODEL=]
          [possible values: true, false]

      --pin-hot-weights [<PIN_HOT_WEIGHTS>]
          Prefetch the always-touched weights (embeddings, norms, attention, routers, shared experts, output) at load and advise random access on routed experts, so the per-token working set stays resident. Defaults to on when the model file is larger than RAM; pass `--pin-hot-weights=false` to force it off
          
          [env: JOSHUA_PIN_HOT_WEIGHTS=]
          [possible values: true, false]

      --pin-hot-experts <PIN_HOT_EXPERTS>
          Keep the N most frequently routed experts resident (routing- frequency LRU; recency as the tie-break).  0 disables.  Wired for the joshua-native MoE loaders (deepseek2, deepseek4, qwen3moe)
          
          [env: JOSHUA_PIN_HOT_EXPERTS=]
          [default: 0]

      --expert-cache <EXPERT_CACHE>
          Size the hot-expert cache automatically at load (`auto`), or set a fixed expert count.  Overrides --pin-hot-experts when given a count
          
          [env: JOSHUA_EXPERT_CACHE=]

      --vram-expert-cache <VRAM_EXPERT_CACHE>
          Size the bounded VRAM expert cache (#62): upload a hot subset of the routed experts to the accelerator.  `auto` derives the device byte budget at load (device free − dense − headroom − KV); a number is a fixed MiB budget; `0` disables (all experts stay on the host). Unset (the default), `--expert-placement auto` engages the cache itself where the leftover device memory is worth it (#110)
          
          [env: JOSHUA_VRAM_EXPERT_CACHE=]

      --ssd-expert-cache <SSD_EXPERT_CACHE>
          Size the Tier-3 NVMe/SSD expert staging slab (`--ssd-expert-cache`): a bounded host-RAM slab that `pread(2)`-streams a hot subset of the routed experts off the SSD (see `NvmeResidency`).  `auto` derives the host-RAM byte budget from the machine's available RAM at load; a number is a fixed MiB budget; `0` disables (experts keep their ordinary host page-cache residency)
          
          [env: JOSHUA_SSD_EXPERT_CACHE=]

      --prefill-chunk <PREFILL_CHUNK>
          Tokens per prefill chunk (default 512).  Bounds the per-layer prefill workspace and sets how many prompt rows each routed expert sees per matmul; the joshua-native MoE loaders read each layer's weights once per prefill whatever the chunk
          
          [env: JOSHUA_PREFILL_CHUNK=]

      --prefill-budget-ms <PREFILL_BUDGET_MS>
          Target wall time for one prefill chunk, in milliseconds.  When non-zero, architectures that prefill chunk by chunk choose each chunk from an online cost model; `--prefill-chunk` is the ceiling. 0 (the default) keeps the fixed chunk size
          
          [env: JOSHUA_PREFILL_BUDGET_MS=]

      --speculative <SPECULATIVE>
          Speculative token generation: draft up to N tokens per step by prompt lookup (the continuation of the latest earlier occurrence of the output's trailing n-gram) and verify them in one forward pass.  Output is unchanged; repetitive output (code edits, quoted context, tool-call arguments) decodes in fewer weight sweeps. `0` (the default) disables it.  Applies to the loaders that can score every position and roll their KV cache back: the plain- attention qwen family (qwen, qwen2moe, qwen2vl, qwen3, qwen3moe, qwen3vl, qwen3vlmoe, chatglm, glm4, glm4moe), the deepseek2 family (deepseek, deepseek2, glm-dsa — incl. V3 / Kimi-K2 / GLM-5), and deepseek4 / deepseek41.  Models with recurrent DeltaNet or KDA layers (qwen3next, qwen3.5, qwen4exp, glm5next, kimi-linear, kimi-k3) and candle's stock loaders cannot roll their KV cache back; there the flag is ignored with a warning
          
          [env: JOSHUA_SPECULATIVE=]

      --mtp <MTP>
          MTP drafting: draft up to N tokens per step (at most 7) with the model's own NextN / MTP block, which GLM-4.5+ and Qwen3.5/3.6 GGUFs carry, and verify them in one forward pass.  Output is unchanged.  Replaces --speculative's prompt lookup on a model with the block and is ignored with a warning on one without.  Every forward pass also runs through the block (one more layer).  `0` (the default) disables it and skips loading the block
          
          [env: JOSHUA_MTP=]

      --draft-model <DRAFT_MODEL>
          Draft-model speculative decoding: a small GGUF that shares this model's tokenizer (e.g. Qwen3-0.6B for a Qwen3 MoE) drafts up to --draft-max tokens per step, verified in one forward pass of this model.  Greedy output is unchanged; sampled output is verified against the draft's own distribution, so it is distributed as plain sampling.  The draft must be an attention-only model of a joshua-native loader (qwen3, qwen3moe, glm4, deepseek2, …) and runs on the dense device.  Takes the place of --speculative's prompt lookup and of --mtp
          
          [env: JOSHUA_DRAFT_MODEL=]

      --draft-max <DRAFT_MAX>
          Most draft-model tokens per step (default 4)
          
          [env: JOSHUA_DRAFT_MAX=]

      --mlock-hot-weights [<MLOCK_HOT_WEIGHTS>]
          Lock the always-touched weights into RAM (mlock).  Needs the process memlock limit to cover the hot set: `LimitMEMLOCK=infinity` (systemd), `ulimit -l unlimited`, or /etc/security/limits.conf. On a systemd *user* session the hard limit is inherited from the login session, so a unit's LimitMEMLOCK alone is silently capped — apply `sudo prlimit --pid <user manager pid> --memlock=-1:-1` for a live fix, or re-login.  `=required` fails the load instead of degrading when the limit is too low; the limit is checked before any mlock attempt, with one warning naming limit vs required size

          Possible values:
          - on:       Lock the hot set; degrade to advisory pinning (with a warning) when the memlock limit is too low
          - required: Lock the hot set; fail the load when the memlock limit is too low
          - off:      Do not lock (explicitly disable, overriding an env var)
          
          [env: JOSHUA_MLOCK_HOT_WEIGHTS=]

      --mlock-weight-budget <MiB>
          Cap locked weight pages in MiB when the full dense set exceeds RAM. Requires --mlock-hot-weights; skips untied input embeddings and routed experts. Leave RAM for KV state and disk staging

      --expert-placement <EXPERT_PLACEMENT>
          Where a MoE model's routed experts live on a GPU: `device` uploads them (the whole model must fit), `host` keeps them in RAM borrowed from the mapping with only the dense set on the GPU (runs models larger than VRAM), `auto` picks `device` only when the model fits the GPU's free memory with headroom.  Ignored on the CPU.  When `auto` falls back to `host` on an architecture that can run routed experts from a bounded VRAM cache (deepseek4 on OpenCL/SYCL), that cache is engaged by default where the leftover device memory is worth it (#110); `--vram-expert-cache 0` opts out
          
          [env: JOSHUA_EXPERT_PLACEMENT=]
          [default: auto]

      --vram-budget <VRAM_BUDGET>
          GPU memory the model may use, in MiB.  Overrides the probe for the `--expert-placement auto` decision and the per-GPU session cap; the way to state the budget on backends without a probe (Metal, OpenCL) or when sharing the card
          
          [env: JOSHUA_VRAM_BUDGET=]

      --npu-plugin <NPU_PLUGIN>
          NPU vendor plugin (a cdylib exporting the joshua_npu_* ABI)
          
          [env: JOSHUA_NPU_PLUGIN=]

      --npu-in-process
          Load the NPU plugin in-process instead of the isolated shim (lower overhead; a plugin crash takes the server down)

      --engram-tier <ENGRAM_TIER>
          Where a DeepSeek-V4.1 model's Engram n-gram tables are resident (a separate policy from the routed experts): `auto` resolves them straight from the mmap mapping (disk-pinned) and promotes a working subset into RAM only when free RAM is ample (>~192 GiB), `ram` always promotes the working subset into RAM, `disk` always pins them to storage.  The tables never consume a Tier-1 VRAM or Tier-2 host-slot budget under any tier
          
          [env: JOSHUA_ENGRAM_TIER=]
          [default: auto]

      --dense-placement <DENSE_PLACEMENT>
          Where the dense set (embeddings, norms, attention, routers, shared experts, output) runs on a GPU: `device` offloads it (right for a real GPU whose GEMM beats CPU-BLAS), `cpu` keeps it on CPU-BLAS (right when the accelerator is a weak iGPU / software OpenCL-Vulkan path that is slower than the CPU), `auto` runs a quick startup probe and picks by measured throughput.  Ignored on the CPU
          
          [env: JOSHUA_DENSE_PLACEMENT=]
          [default: auto]

      --skip-placement-bench [<SKIP_PLACEMENT_BENCH>]
          Skip the `--dense auto` startup probe (fast launch).  `auto` then keeps its historical on-device default, still gated on the dense set fitting the device memory budget (#176)
          
          [env: JOSHUA_SKIP_PLACEMENT_BENCH=]
          [default: false]
          [possible values: true, false]

      --window <WINDOW>
          Tokens per scored window (defaults to the context window)

      --limit <LIMIT>
          Score at most this many tokens (0 = the whole file)
          
          [default: 0]

      --bos
          Wrap the text with the tokenizer's BOS/EOS special tokens

      --json
          Emit one JSON object instead of text

  -h, --help
          Print help (see a summary with '-h')
```

```text

Usage: joshua embed [OPTIONS] --model <MODEL> [TEXTS]...

          - sycl:   SYCL 2020 (Intel oneAPI/LLVM `--features sycl` bridge via a dynamically loaded libjoshua_sycl; build with `--features sycl`; use `--device sycl`)
          
          [env: JOSHUA_DEVICE=]
          [default: auto]

  -h, --help
          Print help (see a summary with '-h')
```
